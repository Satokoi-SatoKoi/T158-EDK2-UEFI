## 2. 关键地址（全部来自 vendor_boot_a 内的基设备树）

基设备树不在 `dtb_a`（该分区全 0），而是**附加在 vendor_boot_a 尾部**（Android boot header v4 的规定位置）：

```
vendor_boot_a @0x4CF0040  size = 0x25C7C (154236)  957 节点 / 4712 属性
```

| 设备 | 节点 | 物理地址 | 说明 |
|---|---|---|---|
| DRAM | `/memory@80000000` | **0x8000_0000**，长度 0x2_0000_0000（8GB） | `reg = <0x0 0x80000000 0x2 0x0>` |
| UART0 | `/soc/ap-apb/serial@0` | 0x20200000 | ap-apb ranges → 0x20200000 |
| **UART1（控制台）** | `/soc/ap-apb/serial@10000` | **0x20210000** | `aliases.serial1`、`chosen.stdout-path = "serial1:115200n8"` |
| UART2 / UART3 | serial@20000 / @30000 | 0x20220000 / 0x20230000 | |
| UFS | `/soc/ap-ahb/ufs@2000000` | **0x22000000**，长 0x10000 | ap-ahb ranges → 0x20000000 |
| SDIO0/1/2 | `/soc/ap-ahb/sdio@22200000` 等 | 0x42200000 / 0x42210000 / 0x42220000 | `sprd,sdhci-r11`，用于 SD/SDIO |
| GICv3 | `/interrupt-controller@12000000` | GICD **0x12000000**(0x20000)，GICR **0x12040000**(0x100000) | `arm,gic-v3` |
| AON | — | 0x64000000，长 0x1016000 | PMIC（ump9620）/ RTC / EIC 在此 |
| PUB | `dmc-controller@60050000` 等 | 0x60000000 起 | DDR 控制器 |
| 架构定时器 | `/timer` | PPI 13 / 14 / 11 / 10 | `arm,armv8-timer` |
| PSCI | `/psci` | `method = "smc"`，`arm,psci-0.2` | |

**串口参数**：`console=ttyS1,115200`（vendor_boot cmdline），`stdout-path = serial1:115200n8`，
compatible = `sprd,ums9621-uart` / `sprd,sc9836-uart`（寄存器布局见 `drivers/tty/serial/sprd_serial.c`）。

### 2.1 DRAM 保留区（固件必须避开）

```
0x80000000-0x80001000  ddrbist      0x80001000-0x80002000  sysdumpinfo
0x87800000-0x88000000  sipc (8MB)   0x88000000-0xA2400000  cp-modem (420MB)
0xA2400000-0xA5000000  nrphy-iqmem  0xA5000000-0xA9000000  iq (64MB)
0xAE600000-0xAE900000  ch_ddr       0xAF700000-0xAFB00000  audio/audiodsp
0xB0000000-0xB4000000  sml/tos      0xB4000000-0xB4100000  sh
0xBE000000-0xBE9E4000  logobuffer   0xBF000000-0xC0000000  sysdump-uboot
0xFFEF0000-0xFFFC0000  uboot_log / ramoops
```
→ **固件选用 0xA9000000 起的 24MB**（iq-mem 与 ch_ddr 之间的空档），其后 32MB 作为 HOB/DXE 内存池。

## 3. 镜像封装格式

### 3.1 DHTB（展锐下载镜像封装）

`uboot_a` / `splloader` / `trustos` / `sml` / `teecfg` 均为 DHTB：

```
偏移 0x00: "DHTB"        偏移 0x04: 0x00000001 (版本)
偏移 0x08..0x27: 校验/签名数据
偏移 0x30: payload 长度 (u32, LE)
```

| 文件 | 文件大小 | payload 长度 (0x30) | 头部 | 尾部 |
|---|---|---|---|---|
| `splloader` | 68,440 | 0x000104A0 (66,720) | 0x200 | 1,208 B |
| `uboot_a` / `uboot_b` | 1,110,280 | 0x0010EA50 (1,108,560) | 0x200 | 1,208 B |
| `trustos` / `trustos_a/b` | 3,409,560 | 0x00340000 | 0x200 | 1,208 B |
| `sml` | 157,224 | 0x00025F90 | 0x200 | 1,208 B |
| `teecfg_a` | 124,568 | 0x0001E000 | 0x200 | 1,208 B |

→ **尾部 1208 字节是签名/证书表尾**，回包时若 payload 等长可用 `--keep-tail` 原样保留（见 `tools/sprd_dhtb.py`）。

### 3.2 Android boot.img（header **v4**）

`boot_a` / `boot_b`：

```
0x00 "ANDROID!"   0x08 kernel_size = 0x2C96A00 (46,693,376)
0x0C ramdisk_size=0  0x10 vendor_ramdisk_size=0  0x14 bootconfig_size = 0x630
0x18 kernel_addr = 0  0x28 header_version = 4   page_size = 4096
kernel 数据 : 偏移 0x1000
```

kernel 是**未压缩的 ARM64 Image**：

```
00001000  4D 5A 40 FA FF 3F 9F 14 ...        "MZ" + 分支
00001038  41 52 4D 64                         magic = "ARMd"  ← 注意不是主线的 "ARM64"
0000103C  40 00 00 00                         PE header offset = 0x40
image_size(0x10) = 0x02D40000   flags(0x18) = 0x0A  (LE + 4K 页 + 可任意放置)
```

> **重要**：magic 为 `ARMd` 说明原厂改过内核头，因此本工程生成载荷时**默认同样写 `ARMd`**
> （`mkpayload.py --magic ARMd|ARM64` 可切换），否则原厂 U-Boot 的 booti 检查可能拒绝启动。

`vendor_boot_a`（100MB）：`VNDRBOOT` + v4
```
0x08 header_version=4   0x0C page_size=0x1000
0x10 kernel_addr = 0x8000      0x14 ramdisk_addr = 0x05400000
0x18 vendor_ramdisk_size = 0x04CEE6E1
0x1C cmdline = "console=ttyS1,115200..."
0x4CF0040 : 附加的基设备树 (0x25C7C)
```

`init_boot_a`（8MB）：v4，ramdisk（0x1F940A 字节）。

`dtbo_a`（8MB）：Android `dt_table_header`（**大端**），magic `D7B7AB1E`，2 个 DTBO 条目
（0x60 / 0x1CFEB），内容只有 LCD、摄像头、sensor 等 **overlay**，没有内存/串口信息。

`vbmeta_*`：`AVB0` 头（1MB）。`fbootlogo` / `logo`：BMP。`pgpt`：GPT 分区表（32KB）。

## 4. 原厂 U-Boot 能力盘点（决定移植路线）

对 `uboot_a` 做字符串取证（6,108 条）：

| 能力 | 是否存在 | 证据 |
|---|---|---|
| **efi_loader / bootefi** | **不存在** | 无 `bootefi`、`efi_loader` 等任何字符串 |
| fastboot | 存在 | `fastboot_handler`、`fb_cmd_download`、`FASTBOOT_MODE` |
| AVB 校验 | 存在 | `secure_avb_verify_image`、`libavb/avb_slot_verify.c` |
| 安全启动 | 存在 | `secure_sign_verify`、`SPRD_CE`、`secboot_unlock_display` |
| Android bootimg 解析 | 存在 | `s_bootimg_info.kernel_offset/ramdisk_offset/dt_offset` |
| eMMC/SD | 存在 | `add_sprd_sdhci`、`sprd_sdhci_init` |
| UFS | 存在 | `ufs-flash`、`vddufs1v2` |
| UART | 存在 | `uart calibrate detecting`、`usb2spuart` |

**结论**：原厂 U-Boot **不能** `bootefi`，所以无法直接跑 `BOOTAA64.EFI`；
固件必须以**内核载荷**的形式被加载（本方案），或自行给 U-Boot 回编 efi_loader（需要 IDH 源码，本工程不采用）。

## 5. 分区表（`分区表.xml` 摘要）

A/B 双分区；与本工程相关的主要分区：

```
splloader(SPL)  uboot_a/b(3MB)  boot_a/b(64MB)  vendor_boot_a/b(100MB)
init_boot_a/b(8MB)  dtb_a/b(8MB)  dtbo_a/b(8MB)  vbmeta_*(1MB)
super(5600MB)  metadata(64MB)  misc(1MB)  persist(2MB)
```

刷写/测试只需要动 `boot_a`（推荐先用 `fastboot boot` 临时启动，不落盘）。
