# 03 · 构建、刷机与验证

> ⚠️ 刷写 bootloader / boot 分区有变砖风险。开始前**务必**备份 `uboot_a`、`boot_a`、
> `vendor_boot_a`、`pgpt`，并确认可以用 ResearchDownload（FDL）强刷救砖。

---

## 1. 环境

* 主机：Ubuntu 20.04 / 22.04（或 WSL2）
* 工具链：`aarch64-linux-gnu-gcc`（Linaro 7.x ~ 13.x 均可，建议 ≥ 7.5）
* Python 3.8+
* EDK2（建议固定版本）：

```bash
git clone https://github.com/tianocore/edk2.git
cd edk2 && git checkout edk2-stable202405
git submodule update --init --recursive
make -C BaseTools/Source/C
```

目录结构（默认约定）：

```
~/edk2/                    EDK2 主仓
<本工程>/edk2/T158Pkg/     平台包
```

## 2. 编译

```bash
cd <本工程>
export EDK2=~/edk2
./build.sh DEBUG
```

等价的手工命令：

```bash
export PACKAGES_PATH=~/edk2:<本工程>/edk2
export GCC5_AARCH64_PREFIX=aarch64-linux-gnu-
cd ~/edk2 && . edksetup.sh BaseTools
build -a AARCH64 -t GCC5 -p T158Pkg/T158Pkg.dsc -b DEBUG
python3 <本工程>/tools/mkpayload.py bootimg -i ~/edk2/Build/T158/DEBUG_GCC5/FV/T158.fd -o payload.img
```

产物：

| 文件 | 用途 |
|---|---|
| `payload.img` | Android boot.img（v4），kernel = UEFI 载荷 |
| `uefi_payload.bin` | 裸载荷（64B ARM64 头 + FD），供 ResearchDownload 封装 |

## 3. 解除 AVB

原厂 u-boot 会对 `boot_a` 做 AVB 校验（`secure_avb_verify_image` / `libavb`）。三选一：

1. **`（推荐）`FDL 方式**：用本目录提供的 `SPRDClientCore.exe` + `FDL_ums9621_T765_T8200`，
   在 FDL2 状态下输入 `dis_avb`（工具 1.5 版支持"一键禁用 avb"，永久生效）。
2. **fastboot**（需要 BL 未锁）：
   ```bash
   fastboot flashing unlock        # 或 fastboot oem unlock
   fastboot --disable-verity --disable-verification flash vbmeta_a vbmeta_empty.img
   ```
   （`vbmeta_empty.img` 可用 `avbtool make_vbmeta_image --flags 2 --padding_size 4096` 生成）
3. **完全不落盘**：`fastboot boot payload.img` —— 部分机型仍会校验，若失败请回到方法 1。

## 4. 启动测试（强烈建议先不落盘）

```bash
fastboot boot payload.img
```

成功时串口（UART1，115200 8N1）会打印：

```

 DT=0xXXXX  DRAM=0x80000000+0x80000000  UART=0x20210000@115200
```

看到 `Shell>` 即达成"进入 Shell 界面"的目标。

## 5. 固化到设备

```bash
fastboot flash boot_a payload.img      # 只改 A 槽，B 槽保留原厂系统，可随时切回
fastboot set_active a                  # 若当前在 B 槽
fastboot reboot
```

回退（若 Shell 不需要了）：

```bash
fastboot flash boot_a <备份的 boot_a>
```

## 6. 串口接线

* 控制台是 **UART1（ttyS1，AP-APB 0x20210000）**，不是 UART0。
* 电平 1.8V，需要 1.8V 的 USB-TTL（CH340/FT232 直接连会烧 IO，务必确认电平）。
* 参数：115200 / 8 / N / 1。
* 找不到 TX 测试点时：可在 u-boot 阶段用 `usb2spuart`（u-boot 字符串里有该命令）把 USB 口切到串口。

## 7. 常见故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 串口完全无输出 | ① 接错了 UART（应接 UART1）② 电平不对 ③ 波特率不对 | 换 UART1/确认 1.8V；改 `PcdUartClockHz`（26MHz↔48MHz）观察字符是否变形 |
| 输出乱码 | 时钟/波特率不匹配 | 调 `PcdUartClockHz`；或确认 `SerialPortInitialize` 里被 u-boot 已初始化的时钟未被破坏 |
| 停在 `SEC:` 第一行不动 | 自搬迁后跑飞 | 检查 `PcdFdBaseAddress`（0xA9000000）是否落在本机保留区之外（见 01 §2.1） |
| 停在 `ArmConfigureMmu` 之后 | MMU 属性/内存表错误 | 检查 `T158PlatformGetVirtualMemoryMap()` 的表项；可先注释 MMU 调用做最小化验证 |
| 找不到 DXE Core | FV 布局问题 | 确认 FDF 中 `FILE DXE_CORE` 的 `[Rule.Common.DXE_CORE]` 生效；确认 `PcdFvBaseAddress/PcdFvSize` 与 FDF 一致 |
| 进不了 Shell，停在 BDS | 内嵌 Shell 的 FILE GUID 不对 | 对照 `ShellPkg/Application/Shell/Shell.inf` 的 `FILE_GUID` 改 `gT158ShellFileGuid` |
| fastboot 报 "FAILED (remote: 'Failed to load/authenticate boot image')" | AVB 未解除 | 回到 §3 |

## 8. 变砖恢复

只要 BootROM 还活着，就可以用 ResearchDownload + `FDL_ums9621_T765_T8200`
（`fdl1-dl.bin` @0x65000800、`fdl2-dl.bin` @0xbefffe00）重新下载原厂 `splloader` / `uboot_a` / `boot_a`。
`addr.txt` 中已给出加载地址，pac 包用 PacCreator 替换对应条目即可。

## 9. 已验证 / 未验证清单（诚实说明）

**已在镜像上验证**（静态取证，见 01 报告）：
SoC/板级身份、DRAM 基址、UART1 基址与波特率、GIC 地址、UFS 地址、boot.img v4 结构、
kernel magic `ARMd`、DHTB 封装与签名表尾长度、原厂 u-boot 无 efi_loader。

**尚未在真机验证**（缺少目标板与 aarch64 编译环境）：
* T158Pkg 的真机编译链接（edk2 版本差异见 02 §5）
* 展锐 UART 寄存器状态位的逐位正确性（`SPRD_UART_STS1` 的 TX_FULL / RX_NOT_EMPTY 位）
* MMU 属性与 Cache 策略在 UMS9621 上的表现
* 固件在真机上的实际启动时序

第一次上机时建议：先把 `PcdBootToShellFirst` 设为 FALSE、`PcdDebugPrintErrorLevel` 开到最大，
确认 SEC 打印正常后再打开 Shell。
